# 需求、贡献和AI协作说明

## 业务需求来源

项目由吴雨泽提出：将日常业务中反复出现的任务分流、渠道经营、商机梳理、经营汇总、方案准备和知识整理，组织为可展示、可复现的公开作品集。

需求方在AI协作过程中明确了六模块范围、事实与推断的区分、结果口径及客户隐私边界，并选择以业务工作流而非模型研发为项目定位。

## 公开版实现

本次代码、测试、模拟数据和说明文档使用AI编码助手辅助实现。公开版为独立重建，没有复制雇主的工作手册、商业材料、客户清单、项目记录或原工作区的代码历史。

公开代码可以支持“定义业务需求、设计流程与验收标准、组织AI辅助实现”的表述；不能仅凭这些文件认定作者独立手写所有代码，或熟练掌握模型训练、算法研究、RAG和分布式系统。

代码中的计算与检查是确定性规则；六份AI任务说明是可手动使用的提示词。没有将规则输出冒充模型生成结果，也没有把人工编写的草稿示例冒充模型实测记录。

## 面试时可解释的设计决策

1. 为什么在途金额不能直接当作销售预测，签约为什么不等于回款。
2. 为什么来源冲突要暂缓，而不是自动采纳最后更新时间较新的记录。
3. 为什么周报只汇总已确认事实，方案与学习模块不能改写业务状态。
4. 为什么结构化字段检查通过后，自由文本仍需人工复核。
5. 为什么公开版使用全新虚构数据，而非只替换客户姓名。

建议作者亲自运行示例并检查失败用例，能够解释以上取舍后再在面试中展开。仓库不提供虚构的节省工时、用户规模或生产部署经历。
